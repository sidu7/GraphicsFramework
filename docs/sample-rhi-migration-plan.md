# Sample RHI Migration Plan - AdvancedRenderingTechniques, RealTimeRayTracing, AnimationTechniques, WaveSimulation

Status: approved plan, implementation not started.
Scope: make every remaining CMake sample target use the current RHI API and render on **both**
OpenGL and Vulkan.
Companion documents: `docs/RHI-Migration-Plan.md` (backend architecture, phases 0-7),
`AGENTS.md` (build/verification rules).

This document is written to be executed step by step by a smaller model. Every phase has an
explicit file list, an acceptance check, and a "do not" list. If a step is ambiguous, stop at the
phase boundary and report; do not invent APIs.

---

## 1. Why this plan exists

`FlockingParticles` and `UnitTests` were migrated to the `Renderer` device API: resources are
created with `Renderer::Instance()->Create*`, shaders are registered with `ShaderRegistry`, GLSL is
`#version 450` with explicit `layout(binding = N)`, and SPIR-V is generated by
`add_framework_spirv`.

The remaining samples are in three states:

| Project | State | Consequence |
|---|---|---|
| `AnimationTechniques` | already on the RHI API, GLSL 450, SPIR-V present | needs regression verification only |
| `WaveSimulation` | already on the RHI API, GLSL 450, SPIR-V present | needs regression verification only |
| `AdvancedRenderingTechniques` | C++ mostly on the RHI API, shaders and registry broken; no Vulkan path | does not render correctly on either backend |
| `RealTimeRayTracing` | predates the RHI, raw OpenGL, old engine API | does not compile |

Two projects are deliberately **out of scope** and must not be modified:

* `IrradianceMapApp/` - standalone CPU utility (RGBE + spherical harmonics), not a CMake target,
  no framework or RHI dependency.
* `GraphicsFramework/VulkanTest/` - legacy raw-Vulkan sample, not a CMake target. Leave it as an
  archive; do not port it to the RHI.

The per-project `CMakeLists.txt` files inside each sample directory are **not used** by the build.
The root `GraphicsFramework/CMakeLists.txt` defines every target through `add_framework_app()`.
Do not add sources or flags to the per-project files.

## 2. Verified baseline (static audit)

These findings are the reason for the ordering below. Do not re-derive them; trust the file/line
references and verify only if the code has changed.

### 2.1 Shader registry

`ShaderRegistry` is a flat map with one entry per integer ID:

```cpp
// Source/Rendering/ShaderRegistry.cpp:37
mShaders[id] = entry;
```

Registering the same ID twice silently replaces the earlier entry. `GetGLSLComputePath()` and
`GetSPIRVComputePath()` read the vertex slot of the same map, so compute and graphics IDs share a
namespace.

`AdvancedRenderingTechniquesApplication::Init()` registers three enums with overlapping values:

| Value | `AppShaderID` | `AppComputeID` | `MotionBlurShaderID` | Final entry (last wins) |
|---|---|---|---|---|
| 1 | `DRAWING` | `BLUR_HORIZONTAL` | `GBUFFER` | MotionBlur `GBUFFER` |
| 2 | `LIGHTING` | `BLUR_VERTICAL` | `MOTIONBLUR_AMBIENT` | MotionBlur `MOTIONBLUR_AMBIENT` |
| 3 | `AMBIENT` | `BILATERAL_HORIZONTAL` | `MOTIONBLUR_LIGHTING` | MotionBlur `MOTIONBLUR_LIGHTING` |
| 4 | `AMBIENT_NO_AO` | `BILATERAL_VERTICAL` | `SKYDOME` | MotionBlur `SKYDOME` |
| 5 | `SHADOW` | - | `TILE_MAX` | MotionBlur `TILE_MAX` |
| 6 | `LOCAL_LIGHT` | - | `NEIGHBOUR_MAX` | MotionBlur `NEIGHBOUR_MAX` |
| 7 | `SKYDOME` | - | `RECONSTRUCTION` | MotionBlur `RECONSTRUCTION` |
| 8 | `AMBIENT_OCCLUSION` | - | `MOTION_BLUR` | MotionBlur `MOTION_BLUR` |
| 9 | `BLUR` | - | - | `BLUR` |

Result: `AllProjects` loads MotionBlur shaders for every ID it uses, and all four compute shaders
resolve to graphics shader paths. This alone prevents both scenes from working.

### 2.2 Shader paths

The registry base path is `res/shaders/`, but MotionBlur's shaders live in `res/motionblur/`:

```cpp
// AdvancedRenderingTechniquesApplication.cpp
ShaderRegistry::Instance()->Init("res/shaders/", ...);
reg->RegisterShader(MotionBlurShaderID::GBUFFER,
    "motionblur/GBuffer.vert", "motionblur/GBuffer.frag",
    "spirv/motionblur/GBuffer.vert.spv", "spirv/motionblur/GBuffer.frag.spv");
```

Neither `res/shaders/motionblur/GBuffer.vert` nor `res/shaders/spirv/motionblur/...` exists, so
every MotionBlur shader load returns an empty source.

### 2.3 SPIR-V generation

`add_framework_spirv()` globs:

```cmake
"${res_dir}/*.vert" "${res_dir}/*.frag" "${res_dir}/*.comp"
"${res_dir}/*.geom" "${res_dir}/*.tesc" "${res_dir}/*.tese"
```

`AdvancedRenderingTechniques/res/shaders/` contains `*.compute`, so no compute SPIR-V is ever
produced. Additionally, `add_framework_spirv` compiles **every** shader under the resource tree, so
an unused broken shader (e.g. `Irradiance.compute`) fails the Vulkan build.

### 2.4 Shader language and bindings

* ART graphics shaders use `#version 420` or `#version 430`; `glslc` (Vulkan env) requires 450.
* Vulkan uses one descriptor set, so UBO and sampler bindings share one namespace. ART currently
  reuses the same numbers:
  * `Ambient.frag`: `Matrices`=2 and `normaltex`=2; `LightData`=4 and `diffusetex`=4;
    `HBlock`=5 and `speculartex`=5.
  * `Lighting.frag`: `Matrices`=2 and `worldpostex`=2; `LightData`=4 and `specularalpha`=4.
  * `LocalLight.frag`: `Matrices`=2 and `worldpostex`=2; `LocalLightData`=4 and
    `specularalpha`=4.
  * `AO.frag`: `worldpostex`=3 and `AOParams`=3.
* In OpenGL the collision is legal (UBO binding points and texture units are separate
  namespaces), which is why the bug is invisible there. On Vulkan,
  `DeviceVK::AllocateDrawDescriptorSet()` skips a resource whose descriptor type does not match
  the reflected binding, so the draw renders with an unbound sampler instead of failing.

### 2.5 std140 array stride

`AllProjects.cpp` uploads packed scalars:

```cpp
block->Init(MAX_BLUR_WEIGHTS_NUM * sizeof(float), 5);          // 101 floats, packed
HUniBlock->Init(sizeof(Hblock), 5);                            // 401 floats, packed
```

but the shaders declare `float weights[101]` and `float Numbers[200]`. In std140, array elements
have a 16-byte stride, so the shader reads the wrong offsets. The blur kernel and the IBL
Hammersley table are both garbage even on OpenGL.

### 2.6 Loose uniforms

Vulkan has no standalone uniforms. The following rely on them:

* `BlurHorizontal.comp`, `BlurVertical.comp`, `BilateralHorizontal.compute`,
  `BilateralVertical.compute`: `uniform int width`.
* All MotionBlur shaders: `uniform sampler2D` without bindings, plus scalars/vectors
  (`windowSize`, `deltaTime`, `k`, `S`, `lightPos`, `Light`, `shadowmat`, `inverseview`,
  `exposure`, `contrast`, `biasAlpha`, `GBufferShow`).
* `RealTimeRayTracing/res/shaders/TraceRay.comp`: `MAX_FLOAT`, `max_passes`, `width`, `height`,
  `Shapes_num`, `eye`, `X`, `Y`, `Z`.

### 2.8 RealTimeRayTracing

`RayTracing.cpp` uses at least four removed API generations:

* `#include "opengl/..."` and `core/...` paths (current: `Rendering/...`, `Core/...`).
* `Engine::Instance().pCamera` and `.scrWidth` (current: `Engine::Instance()->GetCamera()`,
  `Window::Instance()->GetWidth()`).
* `new Shader(path, path)`, `new ComputeShader(path)`, `new ShaderStorageBuffer()` (current:
  `Renderer::Instance()->Create*` + `Init(...)`).
* `Renderer::Instance().DrawAllObjects(...)`, `ShaderStorageBuffer::PutMemoryBarrier()`,
  `Shader::Bind()/Unbind()` (all removed).
* Raw `glGenTextures`, `glTexImage2D`, `glGetUniformLocation`, `glClear` in `Update()`.
* `Scene::Close()` is not overridden, although it is pure virtual.
* `Main.cpp` still uses `Engine::Instance().Start(&proj, 400, 300)`; the current signature is
  `Start(const std::string& settingsFilePath)` plus `SetScene<T>()`.
* There is no `res/Settings.json`.

### 2.9 Vulkan backend gaps that block ART and RT

| Gap | File | Current behaviour |
|---|---|---|
| Offscreen framebuffers | `RHI/Vulkan/FrameBufferVK.cpp:38-61` | passes an uninitialized `VkImageView`, creates no textures |
| Framebuffer bind | `RHI/Vulkan/DeviceVK.cpp:500-502` | empty; every draw goes to the screen pass |
| Clear / depth bind | `FrameBufferVK.cpp:63-79` | empty |
| Depth copy | `FrameBufferVK.cpp:63` | empty |
| Render targets | `TextureVK.cpp:94-99` | `Init(format, w, h)` only stores the values |
| HDR upload | `TextureVK.cpp:60-82` | frees the stbi data and returns; no image is created |
| Pipeline vs render pass | `RHI/Vulkan/ShaderVK.cpp` | one pipeline is created in `Init()` against the screen pass |
| Compute descriptors | `RHI/Vulkan/ComputeShaderVK.cpp:247-315` | every `SetUniform*`, `SetUniformBlock`, `Set*UniformImage` is a no-op |
| Compute dispatch | `ComputeShaderVK::Run` | binds the pipeline but no descriptor set |
| SSBO | `RHI/Vulkan/ShaderStorageBufferVK.cpp:17-50` | every method stubbed; `GetBufferWritePointer` returns `nullptr` |

`RHI/Vulkan/DeviceVK.cpp` already caches bound UBOs and textures in
`mBoundUniformBuffers`/`mBoundTextures` and writes descriptors at draw time. That machinery is the
foundation for the compute work in Phase 5.

## 4. Conventions (apply to every phase)

### 4.1 API

* Resource creation: `Renderer::Instance()->CreateShader()`, `CreateComputeShader()`,
  `CreateFrameBuffer()`, `CreateTexture()`, `CreateUniformBuffer()`, `CreateShaderStorageBuffer()`,
  `CreateVertexBuffer()`, `CreateIndexBuffer()`.
* Shader initialisation: `shader->Init(static_cast<int32_t>(Id))` after
  `ShaderRegistry::Instance()->Init(basePath, registerFn)`.
* Binding: `Renderer::Instance()->Bind*` / `Unbind*`; draws via `Draw`, `DrawQuad`,
  `DebugDraw`, `DebugDrawLines`.
* Never include a backend header (`RHI/OpenGL/...`, `RHI/Vulkan/...`) or `<GL/...>` from a sample.
* Never add `#if defined(RENDERER_*)` outside `Source/RHI/` and CMake.

### 4.2 Shader IDs

Ranges are disjoint per owner and per stage so the flat registry cannot collide:

| Owner | Range | Enum |
|---|---|---|
| AllProjects graphics | 100-109 | `ArtShaderID` |
| AllProjects compute | 300-303 | `ArtComputeID` |
| MotionBlur graphics | 200-209 | `MotionBlurShaderID` |
| RealTimeRayTracing graphics | 400-409 | `RayTracingShaderID` |
| RealTimeRayTracing compute | 500-509 | `RayTracingComputeID` |

Exact values:

```cpp
// AllProjects
enum class ArtShaderID : int32_t {
    NONE = 0,
    DRAWING = 100, LIGHTING = 101, AMBIENT = 102, AMBIENT_NO_AO = 103,
    SHADOW = 104, LOCAL_LIGHT = 105, SKYDOME = 106, AMBIENT_OCCLUSION = 107
};
enum class ArtComputeID : int32_t {
    NONE = 0,
    BLUR_HORIZONTAL = 300, BLUR_VERTICAL = 301,
    BILATERAL_HORIZONTAL = 302, BILATERAL_VERTICAL = 303
};

// MotionBlur
enum class MotionBlurShaderID : int32_t {
    NONE = 0,
    GBUFFER = 200, MOTIONBLUR_AMBIENT = 201, MOTIONBLUR_LIGHTING = 202,
    SKYDOME = 203, TILE_MAX = 204, NEIGHBOUR_MAX = 205,
    RECONSTRUCTION = 206, MOTION_BLUR = 207
};

// RealTimeRayTracing
enum class RayTracingShaderID : int32_t { NONE = 0, RAYTRACE_OUT = 400 };
enum class RayTracingComputeID : int32_t { NONE = 0, TRACE_RAY = 500 };
```

### 4.3 Binding namespace

Vulkan uses a single descriptor set. **Bindings are unique per shader program.** The framework
reserves:

| Binding | Type | Owner |
|---|---|---|
| 0 | UBO `ObjectMatrices` | `Transform::mMatricesUBO` |
| 1 | UBO `MaterialData` | `Material::mMaterialUBO` |

`res/Settings.json` must keep `TransformBindingPoint = 0`, `MaterialBindingPoint = 1` for every
sample. Apps allocate from 2 upward and document their map in this file (sections 6.2, 6.3, 7.2).

Rules:

* Use `layout(binding = N)` only. Never `set =` (invalid in GLSL 4.50 for OpenGL).
* UBOs, samplers, images, and SSBOs all draw from the same number space in Vulkan; a number may
  not be reused inside one shader.
* The same number may be reused in a **different** shader program (e.g. binding 10 is a sampler in
  the display shader and a storage image in the compute shader).
* Prefer `vec4`-only UBO members. `vec3` in std140 occupies 16 bytes; if a `vec3` is used, it must
  be `alignas(16)` in C++ and followed by explicit padding.

### 4.4 UBO array rule (std140)

Any array inside a UBO is uploaded with a 16-byte stride:

```cpp
// count floats, 16 bytes each
std::vector<uint8_t> padded(count * 16, 0);
for (size_t i = 0; i < count; ++i) {
    memcpy(padded.data() + i * 16, &values[i], sizeof(float));
}
ubo->Init(static_cast<uint32_t>(padded.size()), binding);
ubo->AddData(static_cast<uint32_t>(padded.size()), padded.data());
```

Alternatively declare the GLSL member as `vec4 name[N]` and store `glm::vec4` in C++. Do not mix
the two approaches in one block.

### 4.5 Shader rules

* `#version 450` in every file.
* Explicit `layout(binding = N)` on every UBO, sampler, image, and SSBO.
* No loose uniforms of any kind.
* Every shader under a `res/` tree must compile with
  `glslc <file> -o <file>.spv --target-env=vulkan1.2`.
* Compute shaders use `.comp`; never `.compute`.
* Do not change shader math while migrating, except where section 2.7 says a value was never
  set.

### 4.6 OpenGL context

All new shaders are 450. Bump the requested context in `Source/RHI/OpenGL/WindowGL.cpp`:

```cpp
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MAJOR_VERSION, 4);
SDL_GL_SetAttribute(SDL_GL_CONTEXT_MINOR_VERSION, 5);
```

Verify with a one-time log of `glGetString(GL_VERSION)` (or the existing startup log if present).
If the context is below 4.5, stop and report; do not silently fall back to 430.

   ```json

     "TransformBindingPoint": 0,
     "MaterialBindingPoint": 1
   }
   ```

   RT shader deletions happen in Phase 2, not here.

* The file layout is `res/shaders/*.vert|frag|comp` plus `res/shaders/motionblur/*`.

Guardrail: this phase is file moves and deletions only. If a move breaks a `#include` or a

UBO definitions (std140, `vec4`/`mat4` only):

```cpp
struct FrameParamsUBO {
    glm::vec4 windowSizeDelta;   // xy = window size, z = deltaTime, w = k
    glm::vec4 tileNeighbour;     // xy = TileMax size, zw = NeighbourMax size
    glm::ivec4 misc;             // x = S, yzw reserved
};

struct LightParamsUBO {
    glm::vec4 lightPos;          // xyz
    glm::vec4 lightColor;        // xyz
    glm::vec4 ambientColor;      // xyz
    glm::mat4 shadowMatrix;
    glm::mat4 inverseView;
    glm::vec4 tuning;            // x = exposure, y = contrast, z = biasAlpha, w = GBufferShow
};
```

Matching GLSL:

```glsl
layout (binding = 3) uniform FrameParams {
    vec4 windowSizeDelta;
    vec4 tileNeighbour;
    ivec4 misc;
};

layout (binding = 4) uniform LightParams {
    vec4 lightPos;
    vec4 lightColor;
    vec4 ambientColor;
    mat4 shadowMatrix;
    mat4 inverseView;
    vec4 tuning;
};

// Must match MaterialDataUBO in Source/Core/Components/Material.h byte for byte.
layout (binding = 1) uniform ColorData {
    vec4 diffuse;
    vec4 specular;
    float shininess;
    int lighting;
};
```

    DEPTH_STENCIL_ATTACHMENT_OPTIMAL`.
* One subpass with all colour references (`colorAttachmentCount = ColorFormats.size()`) and the
  depth reference (if present).
* **Clear values must not come from `Device::GetClearValues()` any more.** That array has exactly
  two entries (`DeviceVK.h:285`) and is used by the screen pass. Add to `RenderPassVK`:
  ```cpp
  std::vector<VkClearValue> mClearValues;   // one per colour attachment, plus depth last
  uint32_t GetColorAttachmentCount() const;
  bool HasDepth() const;
  ```
  `BeginPass` fills `pClearValues = mClearValues.data()` and
  `clearValueCount = mClearValues.size()`. Populate the colour entries from `Device`'s current
  clear colour (see 9.4) and the depth entry with `{1.0f, 0}`.
* Keep the existing single-format `Init(VkFormat, bool, bool, bool)` as a forwarding overload
  (`{Format}`) so `ScreenRenderPass` and `ImGuiRenderPass` creation sites do not change.

### 9.3 FrameBufferVK: real attachments

Rewrite `Init(int width, int height, ImageFormat format, int Texcount)`
(current body: `FrameBufferVK.cpp:38-61`):

1. Create `Texcount` `TextureVK` objects with `Init(format, width, height)`; store them in
   `m_Textures`.
2. Add `bool TextureVK::InitDepth(int width, int height)`: a `D32_SFLOAT` image with
   `DEPTH_STENCIL_ATTACHMENT | SAMPLED | TRANSFER_SRC | TRANSFER_DST`, plus its view
   (`VK_IMAGE_ASPECT_DEPTH_BIT`) and sampler. Store it in a new `TextureVK* mDepthTexture` owned
   by the framebuffer.
3. Build `RenderPassVK` with the colour formats plus depth:
   `Init(formats, true, false, true, /*bDepthStore*/ true, /*bDepthSampled*/ true)`.
4. Build the `VkFramebuffer` from the colour views (`m_Textures[i]->TexImageView`) + depth view.
5. `ChangeSize` must destroy and recreate the attachments, render pass, and framebuffer.
6. `Delete` must destroy the framebuffer, render pass, textures, and depth texture; guard against
   double deletion (`mFrameBuffer = VK_NULL_HANDLE` after destroy).
7. Add `void SetClearColor(float r, float g, float b, float a)` that updates the render pass clear
   values, and have `Device::SetClearColor` forward to the currently bound framebuffer.

Add `friend class Device;` if `Device` needs direct access.

### 9.4 DeviceVK: bind/unbind offscreen passes

Add to `DeviceVK.h` (private, next to the screen-pass state):

```cpp
FrameBufferVK* mCurrentFramebuffer = nullptr;
bool mOffscreenPassOpen = false;
```

Implement `Device::BindFrameBuffer(const FrameBuffer* framebuffer)`:

1. If a screen pass is open, call `EndScreenPass()`.
2. If `mOffscreenPassOpen`, end the current offscreen pass first (defensive; callers should not
   nest).
3. `const FrameBufferVK* fb = static_cast<const FrameBufferVK*>(framebuffer);`
4. For every colour texture (`fb->m_Textures`) call
   `TransitionLayout(GetCommandBuffer()->mCommandBuffer, VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL,
   VK_ACCESS_COLOR_ATTACHMENT_WRITE_BIT, VK_PIPELINE_STAGE_COLOR_ATTACHMENT_OUTPUT_BIT)`, and the
   same for `fb->mDepthTexture` with `DEPTH_STENCIL_ATTACHMENT_OPTIMAL` /
   `VK_ACCESS_DEPTH_STENCIL_ATTACHMENT_WRITE_BIT`.
5. `fb->mRenderPass->BeginPass(GetCommandBuffer(), fb)` - the pass owns its clear values now
   (section 9.2), so do not touch `Device::GetClearValues()` here.
6. Store `mCurrentFramebuffer = const_cast<FrameBufferVK*>(fb); mOffscreenPassOpen = true;`.
7. `Device::SetClearColor(glm::vec3)`: if `mCurrentFramebuffer` is set, forward to
   `mCurrentFramebuffer->SetClearColor(color.r, color.g, color.b, 1.0f)`; otherwise keep the
   current `ClearValues[0]` behaviour (`DeviceVK.cpp:SetClearColor`).

Implement `Device::UnbindFrameBuffer(const FrameBuffer* framebuffer)`:

1. If `framebuffer != mCurrentFramebuffer`, return (nothing to do).
2. `framebuffer->mRenderPass->EndPass(GetCommandBuffer())` (or `vkCmdEndRenderPass`).
3. Transition every colour texture to `SHADER_READ_ONLY_OPTIMAL`
   (`VK_ACCESS_SHADER_READ_BIT`, `VK_PIPELINE_STAGE_FRAGMENT_SHADER_BIT`), depth to
   `DEPTH_STENCIL_READ_ONLY_OPTIMAL`.
4. `mOffscreenPassOpen = false; mCurrentFramebuffer = nullptr;`
5. Do not reopen the screen pass here; the next `Draw`/`DrawQuad` calls `BeginScreenPass()`.

Guard every draw entry point (`Draw`, `DrawQuad`, `DebugDraw`, `DebugDrawLines`) so it calls
`BeginScreenPass()` only when `mCurrentFramebuffer == nullptr`.

`FrameBufferVK::Clear()`:

* If called while the pass is current (`Device::Get()->mCurrentFramebuffer == this`), no-op:
  clearing already happened at `vkCmdBeginRenderPass` (`loadOp = CLEAR`). ART calls
  `BindFrameBuffer` then `Clear()` for every pass, so this is the common case.
* Otherwise, after ending any open pass, record `vkCmdClearColorImage` for each colour attachment
  (requires `VK_IMAGE_USAGE_TRANSFER_DST_BIT`, already requested in 9.1).
* Keep the method `const`; use `const_cast` locally for the layout member if needed.

`FrameBufferVK::DepthBind()` / `DepthUnbind()`: no-op for now; document why (depth is an
attachment, sampled via `GetTexture`). No sample calls them after Phase 6/7.

### 9.5 ShaderVK: one pipeline per render pass

Current `Init()` (`ShaderVK.cpp:97-260`) fills the state structs locally and creates exactly one
`mPipeline` / `mLinePipeline` against `Device::GetScreenRenderPass()->mRenderPass`. Change to lazy
creation:

1. Move the state structs into members (keep the code that fills them in `Init`, delete only the
   `vkCreateGraphicsPipelines` calls):
   * `std::vector<VkPipelineShaderStageCreateInfo> mStages;`
   * `VkPipelineVertexInputStateCreateInfo mVertexInput;`
   * `VkPipelineInputAssemblyStateCreateInfo mInputAssembly;`
   * `VkPipelineViewportStateCreateInfo mViewport;`
   * `VkPipelineRasterizationStateCreateInfo mRasterization;`
   * `VkPipelineMultisampleStateCreateInfo mMultisample;`
   * `VkPipelineDepthStencilStateCreateInfo mDepthStencil;`
   * `VkPipelineColorBlendStateCreateInfo mColorBlend;`
   * `VkPipelineDynamicStateCreateInfo mDynamicState;`
   * owning vectors for `VertexBindingDescs`, `VertexAttribDescs`, blend attachments, and the
     dynamic-state array, so the pointers in the structs stay valid after `Init` returns.
2. Add:
   ```cpp
   VkPipeline GetOrCreatePipeline(VkRenderPass renderPass, uint32_t colorAttachmentCount);
   VkPipeline GetOrCreateLinePipeline(VkRenderPass renderPass, uint32_t colorAttachmentCount);
   std::unordered_map<VkRenderPass*, VkPipeline> mPipelines;
   std::unordered_map<VkRenderPass*, VkPipeline> mLinePipelines;
   ```
   The cache key is the render pass handle.
3. On a cache miss, build a `VkPipelineColorBlendAttachmentState` array of exactly
   `colorAttachmentCount` entries (blend disabled, `colorWriteMask = RGBA`, same as the current
   single entry at `ShaderVK.cpp:186-196`), point `mColorBlend.pAttachments` at it, set
   `mColorBlend.attachmentCount`, and call `vkCreateGraphicsPipelines` with
   `renderPass = renderPass`. Vulkan requires these counts to match the subpass exactly; a shader
   that writes fewer outputs simply leaves the extra attachments undefined.
4. Create the pipeline on first use; reuse afterwards.
5. `Device::Draw`/`DrawQuad`/`DebugDraw*` call `GetOrCreatePipeline` with the current pass:
   `mCurrentFramebuffer ? mCurrentFramebuffer->mRenderPass->mRenderPass :
   ScreenRenderPass->mRenderPass`, and the pass's colour count from
   `RenderPassVK::GetColorAttachmentCount()`. Bind the returned pipeline instead of `mPipeline`.
6. Keep `mPipeline` / `mLinePipeline` as the screen-pass entry so existing code paths that read
   them still work, or replace every read with the cache lookup. Destroy all cached pipelines in
   `~ShaderVK`.
7. Keep `mLinePipeline` per pass as well (same cache pattern, separate map).

**Why this works:** Vulkan requires the pipeline's render pass to be *compatible* with the bound
framebuffer's pass. Creating one pipeline per exact pass is always compatible, and the cache keeps
the cost at one pipeline per (shader, pass).

### 9.6 Depth copy to the back buffer

`FrameBufferVK::CopyDepthTo(const FrameBuffer* target)` (currently empty,
`FrameBufferVK.cpp:63-65`):

1. `Device* dev = Device::Get();`
2. If a screen pass is open, `dev->EndScreenPass()`. If an offscreen pass is open and it is not
   `this`, unbind it first.
3. Resolve the source image: `mDepthTexture->TexImageInfo.Image`; it must be in
   `DEPTH_STENCIL_READ_ONLY_OPTIMAL` (it is, after `UnbindFrameBuffer` in 9.4).
4. Resolve the destination image from the device, not from `target`:
   `VkImage DstDepth = dev->GetCurrentDepthImage();` where
   `SwapChainImageIdx` indexes `DepthImages` (already a member, `DeviceVK.h:281`). Add:
   ```cpp
   VkImage GetCurrentDepthImage() const { return DepthImages[SwapChainImageIdx].Image; }
   ```
5. `VkImageCopy` with `srcSubresource.aspectMask = srcDstAspect = VK_IMAGE_ASPECT_DEPTH_BIT`,
   `layerCount = 1`, `extent = {mWidth, mHeight, 1}`, `vkCmdCopyImage`.
6. Barrier: source back to `DEPTH_STENCIL_ATTACHMENT_OPTIMAL` (it will be rendered into again next
   frame), destination to `DEPTH_STENCIL_ATTACHMENT_OPTIMAL` (the screen pass renders depth into
   it).
7. `dev->BeginScreenPass()` to restore the frame state.

Prerequisites:

* Swapchain depth images (`DeviceVK.cpp:264`) must be created with
  `VK_IMAGE_USAGE_DEPTH_STENCIL_ATTACHMENT_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT |
  VK_IMAGE_USAGE_TRANSFER_SRC_BIT`.
* The screen pass depth attachment keeps `storeOp = DONT_CARE` today. That is fine: the copy is the
  only thing that needs the destination contents, and it runs after the offscreen pass, not after
  the screen pass.
* Do not create a `TextureVK` for the swapchain depth image; it is never sampled.

Make `FrameBufferVK` a friend of `Device` (`friend class FrameBufferVK;` in `DeviceVK.h`) so it can
call `EndScreenPass`/`BeginScreenPass` and read `mCurrentFramebuffer`; add
`friend class Device;` in `FrameBufferVK.h` for the reverse direction.

## 10. Phase 5 - Vulkan RHI: compute descriptors and SSBO

Goal: ART compute passes and the RT compute pass run on Vulkan.
Depends on: Phase 4 (image layouts, render targets).
Blocks: Phase 6.

### 10.1 DeviceVK accessors

Add to `DeviceVK.h` (public):

```cpp
const UniformBuffer* GetBoundUniformBuffer(uint32_t bindPoint) const;
const Texture* GetBoundTexture(uint32_t slot) const;
```

Return `nullptr` if absent. These let `ComputeShaderVK` resolve `SetUniformBlock` bindings without
duplicating the bind cache.

### 10.2 ComputeShaderVK: descriptor set lifecycle

In `Init` (both overloads):

1. Reflect the SPIR-V once and keep:
   * `VkDescriptorSetLayout mDescriptorSetLayout;`
   * `VkPipelineLayout mPipelineLayout;`
   * `VkDescriptorPool mDescriptorPool;`
   * `VkDescriptorSet mDescriptorSet;`
   * `std::unordered_map<std::string, uint32_t> mBindingByName;`
   * `std::unordered_map<uint32_t, VkDescriptorType> mBindingTypes;`
2. Create the descriptor pool with `VK_DESCRIPTOR_POOL_CREATE_FREE_DESCRIPTOR_SET_BIT` and enough
   descriptors for one set of each reflected type.
3. Allocate one descriptor set.
4. Keep the existing pipeline creation, but reuse the single pipeline layout (remove the duplicated
   loop bodies by extracting a private `CreatePipelineFromSPIRV(const std::vector<char>&)`).

### 10.3 ComputeShaderVK: binding methods

`SetInputUniformImage(name, texture, imageUnit, channels)`:

1. Look up `mBindingByName[name]`; if absent, log once and return.
2. Cache `{binding, texture, VK_IMAGE_LAYOUT_GENERAL}` in a member
   `std::unordered_map<uint32_t, VkDescriptorImageInfo> mImageBindings`.
3. Ignore `imageUnit` for Vulkan; the GLSL `binding` is authoritative. Document this.

`SetOutputUniformImage(name, texture, imageUnit, channels)`:

* Same as input, but the descriptor must be `VK_DESCRIPTOR_TYPE_STORAGE_IMAGE`.

`SetUniformBlock(name, bindPoint)`:

1. Look up the binding from reflection.
2. `const UniformBuffer* ubo = Device::Get()->GetBoundUniformBuffer(bindPoint);`
3. If null, log and return.
4. Cache `VkDescriptorBufferInfo { buffer, 0, size }` keyed by binding.

`SetUniform1i/1f/2f/3f`: keep as no-ops, but add an assertion/log in debug builds. All ART/RT
scalars now live in UBOs, so these are never called by migrated code.

`GetUniformLocation`: return the reflected binding or `-1`.

### 10.4 ComputeShaderVK::Run

1. Ensure the shader initialized (`mPipeline != VK_NULL_HANDLE`).
2. Write the descriptor set with all cached image/buffer bindings (`vkUpdateDescriptorSets`).
3. Allocate a transient command buffer (`CommandQueueType::Graphics`).
4. For every storage image: transition `SHADER_READ_ONLY_OPTIMAL | COLOR_ATTACHMENT_OPTIMAL` ->
   `GENERAL` with `VK_ACCESS_SHADER_READ_BIT | VK_ACCESS_SHADER_WRITE_BIT`
   (`VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT`).
5. `vkCmdBindPipeline(COMPUTE)`, `vkCmdBindDescriptorSets(COMPUTE, layout, 0, 1, &set)`,
   `vkCmdDispatch`.
6. Barrier: `SHADER_WRITE -> SHADER_READ` (`COMPUTE_SHADER` -> `FRAGMENT_SHADER`), then transition
   each storage image back to `SHADER_READ_ONLY_OPTIMAL`.
7. Submit and wait:
   ```cpp
   CommandBufferVK* cmd = Device::Get()->AllocateTransientCommandBuffer(CommandQueueType::Graphics);
   cmd->Begin();
   // ... barriers, bind, dispatch ...
   cmd->End();
   Device::Get()->GetQueue(CommandQueueType::Graphics)->SubmitCommandBuffer(cmd, /*bWait*/ true);
   delete cmd;   // CommandBufferVK's destructor frees the VkCommandBuffer
   ```
   In addition, fix `CommandBufferVK::Init` (`Internal/CommandBufferVK.cpp:23-33`) to store the
   owning pool (`mOwningPool = commandBufferPool;`) so the destructor actually calls
   `vkFreeCommandBuffers`. Today the member is never assigned and every dispatch leaks one command
   buffer. This is a framework bug, not a sample workaround.

### 10.5 ShaderStorageBufferVK

The public interface (`Rendering/ShaderStorageBuffer.h`) has `Bind`, `Unbind`, `CreateBuffer`,
`GetBufferWritePointer`, `GetBufferReadPointer`, `GetBufferReadWritePointer`,
`ReleaseBufferPointer`. There is **no** `PutMemoryBarrier` in the interface; do not add one. The
compute `Run` records the barriers (10.4).

Implement with VMA (all methods in `ShaderStorageBufferVK.h/.cpp`, currently stubs):

* `CreateBuffer(size)`: `Device::Get()->CreateBuffer(size, VK_BUFFER_USAGE_STORAGE_BUFFER_BIT |
  VK_BUFFER_USAGE_TRANSFER_DST_BIT, /*bHostVisible*/ true)`; store the returned `BufferInfo` and
  `mSize`. Keep the buffer persistently mapped through `Device::MapBuffer`/`UnmapBuffer`.
* `GetBufferWritePointer(bool invalidateOldData)` / `GetBufferReadPointer()` /
  `GetBufferReadWritePointer()`: return the mapped pointer; `return nullptr` when the buffer is
  not created.
* `ReleaseBufferPointer()`: `Device::FlushBuffer(mBuffer)` when `invalidateOldData` was false.
* `Bind(unsigned int bindPoint) const`: `Bind` is `const` in the interface, so store into
  `mutable uint32_t mBindPoint;` and register with the device:
  `Device::Get()->SetBoundStorageBuffer(bindPoint, this)` (add the map and accessor to
  `DeviceVK`; the counterpart of `mBoundUniformBuffers`).
* `Unbind(unsigned int bindPoint) const`: `Device::Get()->SetBoundStorageBuffer(bindPoint, nullptr)`.
* Destruction: `Device::Get()->DestroyBuffer(mBuffer)`.

`ComputeShaderVK` must then pick up SSBO bindings for the RT shapes list:
`mBindingTypes[binding] == VK_DESCRIPTOR_TYPE_STORAGE_BUFFER` ->
`Device::Get()->GetBoundStorageBuffer(binding)`; write a `VkDescriptorBufferInfo` with
`offset = 0` and `range = VK_WHOLE_SIZE`.

## 14. Execution guardrails

1. **One phase per commit.** Commit message: `rhi-migration: phase N - <short description>`.
2. **No opportunistic refactors.** Do not rename framework classes, reorder scenes, or reformat
   files outside the phase's list.
3. **No backend headers in samples.** If a fix seems to need one, the fix belongs in `Source/RHI/`.
4. **Binding changes are atomic.** Shader and C++ must change in the same commit.
5. **Every shader must compile.** `glslc` is the gate; a broken unused shader is deleted.
6. **Stop conditions.** If any of these occurs, stop and report instead of improvising:
   * a needed `Renderer` method does not exist;
   * the OpenGL context reports < 4.5;
   * a Vulkan validation error points at framework code not covered by the phase;
   * a build fails for a target outside the phase.
7. **Evidence.** Every phase report includes: files changed, commands run, exit codes, capture
   paths, and the relevant lines from stdout/stderr.
8. **No silent fallbacks.** If Vulkan cannot support a feature, it must be reported and added to
   section 15, not worked around with `#if`.

### 14.1 Known risks and their mitigations

| Risk | Mitigation |
|---|---|
| Bumping the OpenGL context 4.3 -> 4.5 affects every sample | One-line change in `WindowGL.cpp`; verify UnitTests and FlockingParticles first, before ART |
| ART now uses texture units up to 18 | Desktop GL guarantees 16 fragment texture units minimum, usually 32. Log `GL_MAX_TEXTURE_IMAGE_UNITS` once in `AllProjects::Init` and if it is < 19, stop and report rather than compressing the map |
| Compute image units 20-23 | GL guarantees only 8 image units. Log `GL_MAX_IMAGE_UNITS` and `GL_MAX_COMBINED_IMAGE_UNITS` next to the texture-unit log; if < 24, stop and report |
| `HBlock`/`BlurKernel` padding mistakes are silent | Unit-check the uploaded sizes (`3216` and `1616` bytes) and log `sizeof` for the other structs: `Matrices` 192, `DynamicLightData` 80, `LocalLightData` 96, `AOParams` 16, `LightData` 64 (52 bytes of members padded to the 16-byte alignment) |
| Per-pass Vulkan pipelines add complexity | Cache keyed by `VkRenderPass*`; one code path for every pass; no `Renderer` API change |
| Phase 4 can grow unbounded | It has exactly one acceptance artifact (offscreen capture). Do not start Phase 5 until that capture is green |
| `D32_SFLOAT` depth copy fails on some drivers | If `vkCmdCopyImage` on the depth aspect is rejected, report it and fall back to a full-screen depth *sample* instead of a copy; do not silently skip |
| Deleting an "unused" shader breaks a hidden reference | `grep -rn <name> src/ res/` before every deletion |

## 15. Known limitations to document

These are accepted for this migration and must be written into the final docs:

1. `RealTimeRayTracing` renders spheres only. Box/cylinder/triangle intersections remain stubs, as
   in the original code.
2. `Irradiance.compute` and the `Blur` shaders are deleted; the IBL lookup uses the precomputed
   `popDomeIrr.hdr`.
3. `FrameBuffer::DepthBind`/`DepthUnbind` are no-ops on Vulkan. No migrated sample uses them.
4. `ComputeShader::SetUniform1i/1f/2f/3f` remain no-ops on Vulkan. Migrated code uses UBOs.
5. The Vulkan depth copy requires matching `D32_SFLOAT` formats and window-sized targets.
6. MotionBlur's `Color` target and the AllProjects G-buffer are `RGBA32F` and are not blended into
   an sRGB swapchain; the tone mapping difference versus OpenGL is pre-existing.

## 17. Appendix B - Reference snippets

### B.1 Full-screen quad (ART / RT composite passes)

`Renderer::DrawQuad(shader)` creates its own VBO/IBO with positions and UVs, so the vertex shader
must read `location = 0` (vec3) and `location = 1` (vec2):

```glsl
#version 450
layout (location = 0) in vec3 aPos;
layout (location = 1) in vec2 aTexCoord;
out vec2 TexCoord;
void main() {
    gl_Position = vec4(aPos, 1.0);
    TexCoord = aTexCoord;
}
```

### B.2 Compute dispatch helper

```cpp
static uint32_t Groups(uint32_t threads, uint32_t local)
{
    return (threads + local - 1) / local;
}
```
